# 0003 — 资料库、单词库与转换 / 连接器插件（规划，未实现）

日期：2026-10-20
状态：**规划已确认，代码未动**（当前在 P2 收尾，本文件只记录边界与排期）
相关：`docs/ROADMAP.md` P3 / P4 / P5 / P7；`AGENTS.md` 规则 8、12

## 背景

用户提出："接 QQ 自动收老师发的文件并分类/转格式，也可以开数据库存英语单词/笔记"。
讨论后确认它不是一件事，而是三件，且各自依赖不同能力。

## 决定

1. **先做 A 方案（固定文件夹监听 + 拖拽导入）**，把分类 / 去重 / 转换 / 入库做扎实。
   QQ 自动收（B 方案）只作为 **P7 的可选连接器插件**，默认关闭；应用**不实现 QQ 协议、
   不保存 QQ 凭据**，只对接本机 OneBot 桥（NapCat 等），并在文档里写明封号风险。
2. **文件柜与笔记本同层（P5）**，但把"最小资产层"提前到 **P4**：
   错题本要求"原图永久保留"（4.6），需要同一套内容寻址存储；P5 再做文件柜 UI，
   避免 P4 长一套临时图片存储、P5 再迁移。
3. **单词库不是"笔记本类型"**，而是 P3 引入的 **内容模块插件** 之一：
   `notebook`（块文档）/ `wordbook`（结构化词表）/ `file-view`（预览器）。
   硬塞进笔记本会让词表退化成大表格、复习 UI 无处安放。
   单词库 v1 只做 **导入（CSV/TSV/Excel）+ 存 + 查 + 标签**；
   复习队列等 P4-4.8 的 SRS 落地后再接。
4. **转换是独立插件，不是文件柜的一部分**。v1 只做 **"其他文件 → PDF"**：
   Windows 壳调用本机 LibreOffice/Office 转；PWA 没有本机转换器时降级为
   "原样保存 + 浏览器内预览"，并明确提示不能转。
5. **存储策略**：
   - 监听目录**只读**，导入时复制进受管的**内容寻址目录**（sha256 命名），原件不动；
   - PWA 只存预览/元数据；原件留给 Windows 壳（避免 IndexedDB 配额与被清理）；
   - 大文件 Blob **不进 JSON 备份**，备份只包含元数据与相对路径。

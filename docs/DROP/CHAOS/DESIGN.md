## 1. 错题本：模拟扫描 + 混排文档

核心思路不再追求"把题全部 OCR 成文字"，而是：

> **扫描仪化 + 混排文档**：能识别的变成文字，不能识别的（公式、图表、低置信度行）**直接裁图排版**进去。

这就是扫描全能王做的事，也是扫描版 PDF 的经典做法：**可见的图 + 隐藏的文本层**。

### 1.0 处理链路

```
拍照
 → ① 边缘检测 + 透视矫正（四角）
 → ② 光照均衡 / 去阴影 / 对比增强
 → ③ 版面分析：分栏检测 + 行切分 → bbox 列表
 → ④ 逐行 OCR → (文本, 置信度, bbox)
 → ⑤ 分派：
      置信度高 且 非公式 → TextBlock（可编辑）
      置信度低 或 判定公式 → ImageBlock（原图裁剪，按原位还原）
 → ⑥ 组装为「混排文档」，渲染成"看起来像原卷"的页面
```

### 1.0.1 为什么这比全 OCR 好

| 维度 | 全 OCR | 混排 |
|---|---|---|
| 数学公式 | 必须校对 LaTeX，学生痛苦 | 直接贴图，零校对 |
| 校对成本 | 与错误率成正比 | 只校"被转成文字"的那部分，而那部分置信度高 |
| 保真度 | LaTeX 排版可能走形 | 100%（就是原图） |
| 实现难度 | 需公式识别 + 复杂重排 | 只需行级切分 + 两种 block |

### 1.0.2 关键技术点

1. **切块粒度 = 行，不是字符。** 字符级切图会让文档碎成马赛克，无法编辑。
2. **隐藏文本层**：`ImageBlock` 仍保存 OCR 的低置信度猜测（`searchText`），不显示但参与搜索。这解决了"图片不可检索"的致命问题。
3. **位置还原**：ImageBlock 存归一化 bbox + 原图裁剪，渲染时按原宽高比排布，视觉接近原卷。
4. **单栏优先**：多栏版面先降级为"按区域手动框选"，P4 不做全自动多栏重排。
5. **阈值可调**：默认偏高（多贴图、少出错），设置里能调"激进/保守"。
6. **块可升级**：ImageBlock 上有"转 LaTeX / 转文字"按钮（BYOK provider），用户觉得某题值得转时再转，**不强制**。

### 1.0.3 意外的架构收敛（能省很多时间）

混排文档 = **块文档**，而 P5 的笔记也是块文档。

> **错题本的题目块与笔记的块，用同一套数据结构、同一个编辑器。**

块编辑器写一次，P4/P5 共用；上传、渲染、搜索、导出全部复用 → **P5 省 20–30h**。

同时**扫描的 CV 管线**（边缘检测/透视矫正/光照均衡）与**二维码回填的 CV 管线**（fiducial 检测/透视变换/局部采样）是同一套 → 抽成 `packages/vision`，只写一次。

### 1.1 仍要知道的边界（保留自 v0.2）

| 内容类型 | 现实效果 | 混排方案下的处理 |
|---|---|---|
| 印刷体中文题干 | ≈99% 字符准确 | ✅ 转文字 |
| 印刷体数学公式 | 通用 OCR 全废 | ✅ 直接贴图（这正是混排的价值） |
| 双栏 / 多栏试卷 | 行序会串 | ⚠️ 手动框选区域 |
| 表格 | 基本不行 | ✅ 整块贴图 |
| 手写中文 | 60–85% | ⚠️ 默认贴图，可手动转文字 |
| 手写数学推导 | 很差 | ✅ 贴图 |
| 几何图 / 电路图 | 不识别 | ✅ 贴图 |

**原则：任何"做不好"的内容，不降级为错误，降级为图片。** 这条让整个模块永远有出路。

### 1.2 真正的成本仍在校对

一条工程经验：**识别结果只要有 5% 错字，逐字校对的时间往往超过直接重打。**
混排方案把这个成本压到"只校对被转成文字的、且本来置信度就高的行"，这就是它成立的原因。

### 1.3 OCR 必须是可替换的 provider

这类 API 的价格、质量、可用性变化极快，用户也可能想用本地模型：

```ts
interface OcrProvider {
  id: string;
  capabilities: ('printedText' | 'formula' | 'table' | 'layout')[];
  recognize(image: Blob, opts): Promise<OcrLine[]>; // 每行带 bbox + confidence
}
```

内置：本地 PaddleOCR-onnx（离线免费、慢、印刷体够用）、云端 provider（BYOK）、纯手动。

**低置信度不是你实现的缺陷，而是这个方案的设计出口——它永远有地方可以去。**

### 1.4 书写引导与"字体数据"（回应第 5 点）

两件事要分开看。

**(a) 提示用户写好看一点 —— 可以做，但换成「功能性理由 + 物理手段」**

| 做法 | 评价 |
|---|---|
| ❌ 弹窗"请把字写好" | 像指责，每次打扰，体验差 |
| ✅ **把提示印在纸上**：`深色笔 · 不出框 · 不连笔 · 公式写大一点` | 零打扰，且出现在唯一有意义的时刻（下笔时） |
| ✅ **用版式约束代替说教**：书写区加浅色格线/田字格 | 比"提醒"有效得多 |
| ✅ **用数据反馈代替道德提醒**：扫描结果页显示"本次识别率 82%，第 3–5 行按图片保留" | 学生自己会调整 |

**(b) "积累字体数据" —— 建议不做通用模型，改做「本地个性画像」**

为什么不做通用数据积累：

- 训练可用的手写识别需要万级以上标注样本，个人项目采不到有意义的量；
- **笔迹属于可识别个人的生物特征**，属敏感个人信息，未成年人更敏感；
- 同学不会意识到自己在贡献训练数据，这件事本身不太对。

真正有用的替代——**只服务这一个用户，不上传，不训练通用模型**：

| 收集什么 | 用来做什么 | 隐私影响 |
|---|---|---|
| 勾选符号的墨迹占比分布 | 自动校准"已勾选"阈值 | 无（纯像素统计，不留图） |
| 常被误识别的字 → 你的正确写法 | 本地替换表，纠错 | 仅本地 |
| 个人符号习惯（`∵`、`⇒`、自定义缩写） | 展开 / 纠错 | 仅本地 |
| 常用科目 / 章节 | 排序与默认值 | 无 |

这几样加起来效果远好于"采集字体训练模型"，实现成本只有几小时。
**用"个性化"替代"大数据"，是这个项目里反复出现的正确姿势。**

## 2. 「直接接 API 讲解」的注意事项

市面错题本 App 有**后台题库**（题目已被人工标注过题干/答案/解析/知识点）→ 它们是**检索**。
你没有题库 → 只能靠通用大模型**生成**。

### 2.1 生成式的失败模式（必须知道）

| 失败模式 | 表现 |
|---|---|
| 幻觉推导 | 中间步骤算错但结论碰巧对 |
| 几何伪证 | 跳步、"显然成立"、循环论证 |
| 物理边界条件 | 单位、摩擦、理想化假设随手忽略 |
| 编造理由 | 选择题给对了选项，解释是编的 |
| 过度自信 | 语气极其肯定，你无法分辨 |

**这对学生的危险性高于"没有解析"**——因为学生会相信它。

### 2.2 工程上的缓解手段

1. **让模型输出可验证形式**：代数题要求给出 `sympy` 可执行的表达式，本地跑一遍验证；数值题做多组随机代入。
2. **多次采样投票**：3 次独立求解，答案不一致就标"不确定"。
3. **强制结构化输出**：`{ keySteps[], finalAnswer, assumptions[], confidence }`，而不是一段散文。
4. **永远不说"标准答案"**，显示为「AI 参考解析（可能出错，请自行核对）」。
5. **用户反馈回路**：提供"这条解析有错"按钮 → 积累你自己的小标注集 → 以后能过滤坏模型。
6. **缓存**：同一题同一解析复用，避免重复烧钱。

### 2.3 成本与延迟

- 带图 + 长推导：单次几千到几万 token，延迟 10–60 秒。
- 因此必须：**异步任务 + 流式输出 + 后台通知**，不要让用户盯着转圈。
- **BYOK 是关键**：用户填自己的 key → 你不承担成本，也不承担"服务提供者"身份。

### 2.4 隐私

题目照片常带姓名、班级、学校。所以：
- 上传前**可选自动裁剪**到题目区域
- **默认只上传裁剪块**，不上传整页
- 明确提示"此图片将发送给 <服务商>"
- key 本地加密存储，**绝不进日志、同步、崩溃上报**

### 2.5 产品定位（不做任何门禁）

> **默认学生是自觉的。** 不加"先写思路才能看解析"这类门禁——学习工具的价值是降低摩擦，不是增加摩擦。

去掉门禁后，仍然保留三件与"不被误导"有关的事（那不是限制，是准确性）：

- 标注「AI 参考解析，可能出错，请自行核对」，而不是"标准答案"
- 结构化输出 + `sympy` 校验 + 多次采样一致性检查
- "这条解析有错"反馈按钮

**AI 讲解永远不能是核心依赖。** 核心是"你自己的错因标签 + 复习调度"，否则产品价值会随 API 质量剧烈波动。

### 2.6 危机识别：不做

同意。只保留一个静态「求助资源」页（热线列表 + "告诉一个可信任的成年人"），≈1h，不做任何检测逻辑。

## 3. 二维码回填：能不能一步到位做成识别

你的直觉是对的，而且可以做得比"通用 OCR"好得多。

### 3.1 关键洞察

**不需要 OCR。** 因为模板是你自己生成的，你**精确知道每个 checkbox 的坐标**。

于是问题从"识别手写勾选符号"（极难）降级为：

> 在已知坐标的一个小矩形窗口里，判断"有没有笔迹"。

这是个极简的 CV 任务：局部灰度 → 自适应二值化 → 计算前景像素占比 → 阈值判定。**手机端 50–100ms 能跑完一页。**

### 3.2 完整链路

```
P1: 打印时 → 模板渲染同时输出 print_meta.json（每个格子的归一化坐标 + 格子语义）
P2: 手机拍照 → 找到二维码（定日期 + 模板 id + 版本）
      → 用四个 fiducial 角标做透视矫正
      → 按 print_meta 坐标逐格采样
      → 墨迹占比 > 阈值 → 标记"已勾选"
      → 进入"待确认"列表（用户可一键修正）
      → 应用
```

### 3.3 为什么这样准确率高

| 难点 | 通用 OCR | 坐标先验法 |
|---|---|---|
| 手写勾选符号千奇百怪 | 需要分类器，容易错 | 只判断有无墨迹，无歧义 |
| 纸张歪斜/透视 | 严重退化 | fiducial 角标 + 透视变换 |
| 印刷文字干扰 | 会误识别 | 采样窗口只覆盖手写区 |
| 中文手写 | 差 | 无关 |
| 离线 | 需模型 | 纯像素运算，可完全离线 |

### 3.4 降级路径（如果透视矫正做不好）

- 第一版：**二维码只用来定位日期/模板**，勾选状态**手动点**。
- 这已经极大减少输入时间（不用翻日历、不用找清单），成本还很低（≈12h）。
- 笔迹识别作为 P2 的增强，做不出来不影响主线。

### 3.5 一个额外好处

二维码让**同一张纸可以被重复扫描**，且天然带版本号——如果模板改过，`print_meta` 版本不匹配就直接提示"这张纸是旧模板"，不会静默出错。

## 4. 统计类功能的科学性问题

### 4.1 「按科目统计时长」——零额外记录

你的担心是对的：如果每个动作都要打点，用户三天就放弃。

**设计：只采集一次，多处复用。**

- 番茄钟开始时选科目（**本来就要选**）→ 结束时自动生成一条 `session`
- 任务与科目绑定 → 绑定任务时科目自动推断，无需输入
- 一天 5–8 次点击，成本可接受
- 事后提供"快速补录"（5 秒点选时长+科目）
- 知识点维度的统计**不单独打点**，由错题的章节标签在 P4 自然得到

### 4.2 「知识点热力图」——做不到，如实改名

诚实结论：**没有题库、没有标准标签体系、没有足够样本，就做不了"知识点"粒度的科学热力图。**

替代方案（都只依赖你自己的数据，且不宣称科学性）：

| 替代 | 数据来源 | 价值 |
|---|---|---|
| **章节错题密度** | 错题的章节标签 | 哪里错得多，一目了然 |
| **SRS 复习状态** | FSRS 的 `stability` / `difficulty` | 哪些卡快忘了 |
| **复习正确率趋势** | 每次复习的四档评级 | 真实进步曲线 |
| **标签共现** | 错因标签组合 | "我总是审题错"这种洞察 |

标签体系的**唯一可用骨架 = 教材目录**（人教版/北师大版章节树）。这是唯一学生认可、有权威性、且可获得的分层结构。让用户导入/编辑一棵章节树即可。

**命名建议**：不要叫"知识图谱""学情诊断"，叫「**我的错题分布**」。不宣称科学性反而是最科学的做法。

### 4.2.1 打卡与学习记录**不互相推导**

这两件事看起来都能说明"我今天学了"，但语义不同：

| | 打卡 | 学习记录 |
|---|---|---|
| 语义 | 我承诺做某件事，并对自己负责 | 我实际花了多少时间 |
| 数据源 | 用户手动勾选（`habitLogs`） | 番茄钟 / 纸面登记（`sessions`） |
| 失败方式 | 忘勾 → 数字偏低（诚实） | 忘记 → 数字偏低（诚实） |

**不要用学习记录自动给打卡打勾。** 否则打卡数字会虚高，用户也分不清哪个是自己真正坚持的。
首页的「连续学习」按 sessions 算，打卡的连续天数在打卡页按 `habitLogs` 算，两者互不引用。

### 4.3 「睡眠/心情/专注相关性」——学校可用性

学生在校不能掏手机。解法是**把记录压到 3 秒，且支持纸上完成**：

- 每天睡前 1 次，3 个滑块（睡眠时长 / 心情 / 专注），≈10 秒
- 或者：每个番茄结束后 1 击打专注度（零额外步骤）
- **上学日**：打印模板上有三个手写小格（`slots` block），回家扫码回填
- 相关性分析用简单统计即可：分箱均值 + Spearman 相关。不需要机器学习。

## 5. 对象存储预签名 URL（技术解释）

### 5.1 先看朴素方案错在哪

```
客户端 ──上传文件──> 你的服务器 ──写入磁盘──> 你的磁盘
```

问题：所有流量走你的服务器（1 核 VPS 会被传文件打满）、Node 进程要吃文件内存、磁盘和备份都翻倍。

### 5.2 S3 的分工

```
客户端 ──①要一个上传地址──> 你的服务器（只做鉴权）
       <──②返回签名 URL────
客户端 ──③直接 PUT 文件───> 对象存储（MinIO / S3 / R2 / B2）
```

**文件字节全程不经过你的服务器。** 你的服务器只做"发门票"。

### 5.3 原理

对象存储需要一对密钥（`accessKey` + `secretKey`）才能写。这对密钥**绝不能下发给客户端**。

但持有 secretKey 的一方，可以为一个**特定的、短时的、单次的操作**计算签名，拼进 URL：

```
https://minio.example.com/gofor/u/8f3a.../abc.jpg
  ?X-Amz-Algorithm=AWS4-HMAC-SHA256
  &X-Amz-Expires=300
  &X-Amz-SignedHeaders=host
  &X-Amz-Signature=9c1e...
```

持有这个 URL 的人，在 300 秒内可以**对这一个对象做这一个操作**，不需要再经过你。
对象存储收到请求后自己重新验算签名。

### 5.4 完整上传流程

```
1. client → server: POST /files/upload-url { name, size, mime, sha256 }
2. server: 鉴权、查配额、校验类型/大小
        → 生成 presigned PUT（5 分钟、限 content-length、key 带随机前缀）
3. client → MinIO: PUT <presigned>   ← 直传，不过 server
4. client → server: POST /files/confirm { key, sha256 }
5. server → MinIO: HEAD 校验存在 + 大小 + 哈希一致 → 落库
```

下载同理，用 presigned GET（有效期更短）。

### 5.5 安全要点

| 要点 | 原因 |
|---|---|
| 有效期分钟级 | 防止 URL 被转发后长期可用 |
| `content-length-range` 策略 | 防止客户端绕过大小限制 |
| key 含随机前缀 / UUID | 防止枚举 |
| **必须服务端 confirm**（HEAD 校验） | 否则客户端可伪报上传成功 |
| bucket 绝不设公共读 | |
| sha256 去重 | 省空间，重复文件直接引用 |
| 签发接口限流 | 防止被当作免费存储 |

### 5.6 对私服场景的意义

- 你的服务器可以极小（几乎不承载流量）
- 私服用户可以直接用 **Cloudflare R2**（免费额度大、无出站费）或自家 NAS 上的 MinIO
- 如果只是"和好友传文件"，其实**存进去 + 发个链接**就够了，不需要单独的"文件传输"模块

### 5.7 更简单的替代（如果觉得 S3 太重）

自托管场景下也可以：**nginx `X-Accel-Redirect` + 一次性 token**，或直接把文件放本地盘、用带 HMAC 签名的短链。原理相同，实现更轻。

## 6. SRS 算法选型

不要自己发明调度算法。选：

| 方案 | 说明 |
|---|---|
| **FSRS**（推荐） | 目前公开算法里最先进，Anki 已在用；有开源实现和参数拟合工具 |
| **SM-2 变体** | 极简，20 行代码，效果够用；适合 P4 第一版 |
| 自创 | ❌ 你会花两周调参，然后发现不如 SM-2 |

建议：**P4 先上 SM-2 变体**（半天实现），跑一个月收集自己的复习日志 → 有几百条记录后再换 FSRS 并拟合参数。这本身也是个很好的插件化案例。

关键设计：复习项与番茄钟联动——"刷 15 分钟错题"就是一个特殊的番茄会话。

## 8. 纸张优先（由"在校不能用手机"推出的第一设计律）

这条约束一出现，产品主线就反转了：

> **纸不是输出端，纸是「主输入端」。**

推论，按重要性排列：

1. **每日闭环必须在纸上完成**。任何"每天必须打开手机/电脑"的设计都是错的。
   - 每天：在纸上打勾、（偶尔）划一格专注格、写 1–3 行起止时间。
   - 回家：**1 次拍照**（≤30 秒）+ 确认修正（≤1 分钟）。
2. **屏幕侧的功能要么"占用时间少"，要么"非每日必须"。**
   - 每日必须且费时的功能（预估耗时排程、复杂设置）→ 砍或推到周末。
3. **纸上要能表达"量"，不能只有勾。** 打勾只能给布尔值，给不出时长。
   - 解法有两种，按场景分工：**在校用「专注格」**（预印课表 + 例外登记，一划即算，多数日子 0 笔）；
     **在家用「时间登记」**（写做了什么 + 起止，顺便拿到"几点学的"这种专注格拿不到的数据）。
     两者产出同一种 `StudySession`。完整对比见 §9。
4. **模板必须自解释**：不看 App 也知道怎么填，纸丢了也不影响（有手动补录兜底）。
5. **必须容忍纸的物理现实**：折叠、脏污、倾斜、笔迹渗透背面 → 扫描流程要能容忍折痕和低对比度。
6. **省纸**：学生不会带一叠纸。默认模板 A5 一张管一天，或 A4 一周一张。
7. **每周一次屏幕侧大循环**：扫描回填 → 看周报 → 打印下周的纸。这是唯一允许"重"的操作。

### 8.1 由此带来的节奏

| 频率 | 在哪 | 做什么 | 时间 |
|---|---|---|---|
| 每 25/45 分钟 | 纸 | 涂一格番茄 | 0 秒 |
| 每天 | 纸 | 打勾、写 1–3 个数字 | 30 秒 |
| 每天（回家） | 手机 | 拍 1 张照片 + 确认 | ≤2 分钟 |
| 每周（周末） | 电脑/手机 | 扫描回填全部、看周报、打印下周 | 20–30 分钟 |
| 每月 | 电脑 | 复盘、调整模板 | 30 分钟 |

**任何新功能都要先回答：它落在上面哪一行？如果落在"每天都要在屏幕上操作"，它就有问题。**

## 9. 纸上的时间怎么记：专注格 vs 时间登记

两种机制都能还原学习时长，成本结构不同。**结论：按场景分工，不要二选一。**

### 9.1 对比

| | 专注格（勾/涂） | 时间登记（写起止） |
|---|---|---|
| 每次操作 | 找到行 → 划一笔 | 写 4 位数字 |
| 需要看钟 | **不需要** | 需要 |
| 要写的内容 | 无 | 做了什么 + 起止 |
| 能还原 | 时长、分科 | 时长、分科、**几点学的** |
| 漏记能否恢复 | 能（事后补勾） | 只能估 |
| 版面前提 | 需要预印科目行 | 不需要预印 |

### 9.2 你的担心成立：涂满确实太繁 —— 改两点

1. **不必涂满，一划即可。** 方块只是一个**定位框**（扫描时按已知坐标采样），
   有任何笔迹超过阈值就算完成。划一笔的成本约为涂满的 1/4。
2. **在校时段由课表预印**，行和格子都是排好的，不用"找行、找下一个空格"。

### 9.3 但"完全改用时间登记"会丢掉三样东西

| 丢失 | 后果 |
|---|---|
| 不用看钟 | 教室里没表/在听课，写时间就是额外负担 |
| 漏记可恢复 | 忘记写开始时间 = 这段完全丢失，而勾可以事后补 |
| 预印带来的零决策 | 空白时间表会变成"空白页压力"，导致干脆不填 |

### 9.4 建议：按场景分工

| 场景 | 机制 | 每日操作量 |
|---|---|---|
| **在校课时** | 预印课表 + **例外登记**（默认全完成，只圈"这节没学"） | **0–2 笔** |
| **在家 / 自习** | **时间登记**（写做了什么 + 起止），按上午/下午/晚上分栏 | 1–3 行 |
| 用 App 时 | 番茄钟自动记录，纸上不用记 | 0 |

**例外登记是关键**：课表已经告诉你"这段时间本该做什么"，所以只需要记录偏差，而不是记录全部。
大多数日子在校是 **0 笔**——这比涂 9 个格子省一个数量级。

同时它也顺带回答了"专注格太繁"：如果连划一笔都不想做，可以关掉在校那块，
只保留"自主时间登记"，`print.focusGrid.enabled = false` 即可。

### 9.5 好消息：两种机制产出同一种数据

```ts
interface StudySession {
  date: string;
  start: number;            // 当日第几分钟
  end: number;
  subjectId?: string;
  taskId?: string;
  source: 'paperTime' | 'paperGrid' | 'appTimer';
}
```

| 来源 | start | end |
|---|---|---|
| 时间登记 | 手写 | 手写（只写开始则按默认时长补） |
| 专注格 | 由课表时段推出 | `start + unitMinutes` |
| App 番茄钟 | 精确 | 精确 |

统一后，统计 / 周报 / 相关性分析**只写一套**。这也是选择"混着来"的最大理由。

### 9.6 专注格仍然保留的定义

- **行** = 一个科目（或"自习/作业/复习"等伪科目），由当天课表自动生成
- **格子** = 一个专注单元，单位由 `focus.unit` 决定（默认跟随作息表推导）
- **状态** = 有笔迹 / 无笔迹（**不支持半格、不支持颜色区分**——会让墨迹检测阈值变模糊）
- 还原：`有笔迹格数 × resolveUnitMinutes(config)`

### 9.7 时间登记的歧义：靠版面消除，不靠算法猜

「7:30」在上午栏是 07:30，在晚上栏是 19:30。**不要在解析器里猜**，让版面承担这个信息：
纸面时间区按 **上午 / 下午 / 晚上** 分栏，栏标题就是 `dayPart`。

已实现 `packages/core/src/paper/timeRange.ts`：

- 支持 `19:30` / `1930` / `19.30` / `19点30分` / `19:30~20:15` / `19:30到20:15` / 跨零点 `23:30-0:30`
- 全角自动转半角
- **解析不出来就明确失败**，进待确认列表，绝不瞎猜
- 只写开始时间时 `end = null`，由调用方套默认时长

## 10. 配置体系：不确定的都不写死

### 10.1 三级配置

| 层 | 位置 | 谁改 | 例子 |
|---|---|---|---|
| 默认值 | `packages/core/src/config/defaults.ts` | 开发者 | 默认 A5、默认 4 个番茄后长休息 |
| 用户配置 | 本地存储（Dexie），UI 可改 | 用户 | 纸张尺寸、课时、墨迹阈值 |
| 导出 JSON | 随数据一起备份/分享 | 用户 | 换设备、给同学抄配置 |

**任何来源的配置都必须过 zod schema 校验**（`parseConfig` / `mergeConfig`），
不能因为"这是我们自己写的默认值"就跳过。

### 10.2 什么该配置化，什么不该

这是最容易失控的地方。判断标准只有一条：

> **「现实世界会变」的 → 配置化；「产品设计决定」的 → 不配置化。**

| 应该配置化 | 不应该配置化 |
|---|---|
| 课时长度、作息表（每校不同） | 交互流程（番茄结束后做什么） |
| 科目列表、教材目录（每人不同） | 数据模型（块/文档结构） |
| 纸张尺寸、模板选择 | 视觉风格（配色、间距） |
| 墨迹阈值、识别灵敏度 | 同步协议 |
| 番茄时长与休息节奏 | 快捷键的默认值（可调但别做成 UI） |

**反面警告**：配置项超过 ~40 条就说明设计在失控——每一项都是测试面和文档负担。
新加配置前先问："能不能从已有的东西推导出来？"

### 10.3 派生优先于手填

> **能从课表/作息表推导的，绝不让用户手填。**

这是 `focus.unit = 'period'` 的意义，也是 `periods` 放在配置根目录的原因：

```
作息表 Periods（随课表导入：ICS / 手工 / 拍照）
  ├→ 一节课多少分钟        → 专注格单位
  ├→ 默认番茄时长          → 番茄钟
  ├→ 课表渲染的时间轴
  ├→ 限时套卷的分段提醒
  └→ 打印模板上的课表区块
```

**只在源头存一份**，其余全部在读取时计算。改一次作息表，全系统跟着变。

### 10.4 配置项的迁移

`schemaVersion` 必须随每次破坏性改版 +1，并写迁移函数。
用户可能把旧配置留在手机上一年。**配置迁移失败 = App 打不开**，比数据迁移失败更致命。

## 11. 打印模板：可拼装的纸

### 11.1 两种时间记法都是普通组件

`focusGrid`（在校专注格）与 `timeLog`（自主时间登记）**都是普通 block**，
任何模板都可以只放其中一个、两个都放、或者都不放。没有"默认方案"这回事，只有模板内容。

```jsonc
{
  "id": "day-a5",
  "name": "我的一天",
  "paper": "A5",
  "margin": { "top": 8, "right": 8, "bottom": 8, "left": 8 },
  "blocks": [
    { "id": "t",  "kind": "title",      "span": 12, "text": "{{date}}", "align": "left" },
    { "id": "tk", "kind": "checkboxList","span": 12, "bind": "tasks.today", "rows": 5 },
    { "id": "fg", "kind": "focusGrid",  "span": 12, "bind": "subjects.today",
      "rows": 4, "cells": 5, "unitMinutes": "period" },
    { "id": "am", "kind": "timeLog",    "span": 12, "dayPart": "morning",   "rows": 1, "label": "上午" },
    { "id": "pm", "kind": "timeLog",    "span": 12, "dayPart": "afternoon", "rows": 1, "label": "下午" },
    { "id": "ev", "kind": "timeLog",    "span": 12, "dayPart": "evening",   "rows": 2, "label": "晚上" },
    { "id": "sl", "kind": "slots",      "span": 12, "labels": ["睡眠", "心情", "专注"] }
  ]
}
```

想要"只用时间登记、不要专注格"？把 `fg` 那行删掉就行。**不需要两套代码路径。**

### 11.2 版式模型：12 列网格 + 固定高度

**不用浮动布局，不用绝对定位自由拖拽。** 理由：

| 方案 | 问题 |
|---|---|
| 自由画布（Canva 式） | 重叠、分页不可预测、"预览好打印歪"、撤销重做要自己写——这是另一个产品 |
| 自动撑开（内容多高就多高） | 每页都要运行时测量 DOM，打印结果依赖字体加载，不可复现 |
| **12 列网格 + 显式高度** ✅ | 纯算术、可单测、可复现、能生成回填坐标 |

规则：

1. 区块按声明顺序**纵向流式**排列；本行放不下就换行。
2. `span` 1–12 控制横向占比（12 = 整行，6 = 半行，4 = 三分之一）。
3. **高度由区块自己算**：`高度 = 内边距 + 行数 × 行高`。
   **行数是显式参数**，不是从数据推出来的 —— 数据多了缩字号或提示截断，不悄悄撑破版面。
4. 超出一页自动换页；`pageBreak` 区块强制换页。
5. 单块高于整页时**明确丢弃并告警**，绝不偷偷裁掉半块。

已实现 `packages/core/src/print/`（`layout()` / `fitsOnePage()` / `normalizePlacement()`），19 个单测。

### 11.3 实测结论：A5 装不下完整混合版

按上面的参数实测：

| 组合 | 高度需求 | A5 可用 194mm |
|---|---|---|
| 清单 8 项 + 专注格 + 三段时间登记 | ≈210mm | ❌ 装不下 |
| 清单 5 项 + 专注格 + 两段时间登记 | ≈157mm | ✅ |

所以：**完整混合版必须 A4，A5 只能放精简版。** 这不是拍脑袋，是 `fitsOnePage` 算出来的，
以后加/减 block 时它会立刻告诉你超了多少。

### 11.4 模板编辑器分两期

| 期 | 能力 | 工时 |
|---|---|---|
| **P1 v0（列表式）** | 左侧组件面板（拖入 / 点击添加）→ 中间纸张预览 → 右侧属性（行数、span、绑定）→ 拖拽排序 → 实时溢出提示 | ~14h |
| **后期** | 自由定位画布（真·随便拖到任意位置） | 记入 LATER，不进主路径 |

**为什么 v0 不做自由画布**：你需要的 80% 是"选哪些块、按什么顺序、多大、几行"。
列表式 + 预览已经完整覆盖，而自由画布会把工时翻三倍，却不会让你多打印一张纸。

### 11.5 三个必须提前解决的坑

**① 内容长度可变**
模板说 `rows: 5`，但今天有 9 项作业。规则：**只渲染前 5 项 + 一个「+4 项见 App」的角标**，
或者模板提示"改成 rows: 9"。**不做自动缩小字号**——缩小后手写空间不够，纸就废了。

**② 打印校准页**
已做一张 `calibration` 模板：近似 10mm 刻度 + 四角定位标。
打印一次就能回答"我的打印机有没有缩放、边距够不够、fiducial 有没有被裁掉"。
**这是所有"打印出来不对"问题的通用解法**。精确 1mm 刻度需要新增 `ruler` block（见 LATER）。

**②.5 定位点（当前实现，2026-10-20）**
每页四角 3mm 定位块：上方/左右离页边 4mm；下方两个跟着页尾条码走（正文底部 + 1mm），
但不越过页脚安全线（A4≈11mm、A5≈8mm），避免打印机最下方不可打印区。
此外每个区块在 2mm 行距里印两个 1.2mm 对角小十字：页面级透视矫正解决不了纸张局部
拉伸，扫描端用这两个点对每个区块再做一次平移 + 等比缩放校正；找不到就退回页面坐标。
所有定位点都用 SVG 矢量绘制，不依赖浏览器「背景图形」选项。

**③ 浏览器打印的固定套路**
- 关闭页眉页脚（浏览器默认会打 URL 和日期）
- 缩放必须 100%（"适合页面"会破坏毫米精度）
- 必须勾选"背景图形"（否则浅色格线全丢）
- `@page { size: A5; margin: 0 }`，页边距由我们的 mm 布局负责，不交给浏览器

这三条写成一屏"打印前检查"提示，放在每次打印的按钮下方。

### 11.6 坐标元数据随版式生成

`normalizePlacement()` 把每个区块转成 0–1 的归一化矩形。
扫描回填时按 fiducial 做透视变换，再乘归一化坐标就能定位每个格子——
**与扫描分辨率、手机型号、拍摄角度全部无关。**

因为版式是纯算术，这套坐标是**编译期就能确定**的，不需要真的渲染一遍浏览器。

坐标清单目前记录：每个可回填格子的归一化矩形、所属区块 id、每个区块的矩形与两个
小定位点、以及这一页下方定位点的纵坐标（`fiducialBottomTopMm`）。
扫描端先按四角定位块做整页透视矫正，再按区块小点做局部校正，最后才乘归一化坐标采样。

## 15. 数据安全与故障兜底（P1 收尾补的）

P1 功能做完了之后回头审，最大的问题不在功能，在**"数据只有一份、坏了就没了"**。
这一节记下判断依据，免得以后又回到只靠自觉。

### 15.1 数据会以三种方式丢

1. **浏览器驱逐**：磁盘紧张时，浏览器可以静默清掉"未持久化"的来源数据（IndexedDB 也在内）。
2. **用户清缓存 / 卸载 / 换设备 / 重装系统**：本机存储没有第二份。
3. **渲染崩溃**：数据还在库里，但界面进不去。历史上真发生过——在 Dexie `liveQuery` 里写数据
   抛 `ReadOnlyError`，整棵树被卸载，白屏，用户只能清缓存（清了数据就真没了）。

前两种是"数据没了"，第三种是"数据还在但用不了"。解法不同，要分开防。

### 15.2 三道防线（已实现）

| 防线 | 做法 | 防的是 |
|---|---|---|
| 持久化存储 | 启动时调 `navigator.storage.persist()`（失败静默） | ① 驱逐 |
| 备份提醒 + 一键导出 | 距上次备份 ≥ `config.backup.reminderDays`（默认 7 天）时顶部出现横幅，点一下用 `exportAll` 导出 JSON 并记录时间 | ② 换设备/清缓存 |
| 导入导出可往返 | e2e 真下载一次、再导入一次，并覆盖"坏文件"提示路径 | 备份文件到底能不能用 |

原则：**提醒要挡在视线里，但不能挡路**。「今天不再提醒」写进本机，当天不再弹。
不做弹窗、不做强制、不拦操作——工具是降摩擦的（AGENTS 规则 6）。

### 15.3 没做的，以及为什么

**无人值守的自动备份**（记在 `docs/LATER.md`）。浏览器里真正"静默写盘"只有
File System Access API：需要用户授权一次，之后拿到目录句柄才能反复写。它在
Chrome/Edge 可用，Android WebView 与部分内核支持不一致，而跨设备备份本来就要服务端（P7）。
"提醒 + 一键"已经覆盖主要场景，再往上做就变成自建同步服务了，不是 P1 该做的事。

### 15.4 故障兜底（渲染层）

- 根 `ErrorBoundary`（`apps/web/src/main.tsx`）：渲染异常不再白屏，显示错误摘要 + 重试 + 重新加载。
- `ScreenBoundary`：外壳按页面包裹，切页自动清错误——**单页崩不影响导航和其他页面**。
- 打印层独立于屏幕层：屏幕崩了，已生成的版式仍然能打（`PrintLayer` 本就在 `.screen-only` 之外）。
- 规则写进 `AGENTS.md`：新增页面必须包 `ScreenBoundary`。

边界**兜不住**事件处理器与异步回调里的异常（React 本身抓不到），那些只能在源头处理；
所以 `liveQuery` 只读这条规则仍然必须遵守。

### 15.5 这一轮的验收标准

修问题不是"改完看起来对了"，下面每条都要有证据：

1. `pnpm verify` 退出码 0（typecheck + 单测 + build + e2e）
2. 单测数量只增不减：新增纯逻辑（课表网格/作息表校验/打卡查询/导出补全）必须有测试，**新增 ≥ 20 条**（实际新增 38：core 31 + config 5 + store 2）
3. e2e 只增不减：新增导入、导出、坏文件、「备份含全部表」四条路径，既有 check 一条都不许删（31 → 42）
4. `navigator.storage.persist()` 被调用，失败/不支持时不崩
5. 渲染异常显示兜底 UI，而不是白屏（临时注入异常验证后回滚）
6. CI 在 push / PR / 手动触发时跑 `pnpm verify`
7. `Timetable.tsx` 拆分到 ≤ 300 行（实际 214），纯计算搬进 `packages/core/src/timetable` 并有单测
8. 不删除任何已有功能：导航条目、屏幕、模板、区块种类数量不减

## 16. 纸的回流（P2）

P1 的纸是单向的：程序打印、人写、数据留在纸上。P2 要把纸上的勾选读回来。
**不做通用 OCR**——先验比识别可靠得多。

### 16.1 为什么是「坐标先验」而不是 OCR

我们**知道**每个格子应该在纸的哪个位置：版式引擎本来就是纯算术，能给出毫米坐标。
所以识别问题从"读懂手写/印刷文字"降级成"这个已知矩形里有没有墨"。
- 不需要训练模型、不需要联网、不引入 OCR 体积
- 准确率由纸张摆放与透视矫正决定，而不是由字迹决定
- 失败是**局部的**：某一格读不准，用户勾一下就行

代价：纸必须由本程序打印（坐标表要匹配），拍照要大致正对着纸。

### 16.2 链路

```
打印 ──► 固化坐标清单（SheetManifestRecord，按 模板+日期+纸张 存在 Dexie）
      └► 纸上印二维码：gofor://fill?v=1&t=<模板>&d=<日期>&p=<纸张>

拍照 ──► 手动点四角（自动检测兜底）──► 透视矫正（warpQuad）
      └► 灰度 + Otsu 二值化
      └► 按坐标清单逐格算墨迹占比（inkRatio）
      └► 阈值判定（默认 0.18，可调）
      └► 生成 ScanBatch(pending) ──► 待确认列表 ──► 用户点「应用」才写数据
```

三个刻意的选择：
1. **打印时固化清单**。回填时若重新推导，中间改过作业顺序就会把勾记到别人头上——
   静默错数据比识别不出来严重得多。
2. **一律先进待确认**。识别结果永远不当成事实；用户确认后才写。
3. **局部坐标先验**。只读"已知矩形里的墨迹"，不推断文字内容。

### 16.3 读不了的手写区（明确不做）

- **时间登记**（`19:30` 这种手写时间）：需要数字识别，P2 不做；时间继续在界面上手动补。
- **三手写小格**（`slots` 区块）：同上。要回填三滑块，用新增的 `ratingGrid` 区块——打印成
  1–5 的勾选格，墨迹检测就能读出数值。
- **课表/表格里的文字**：只读"这一行有没有被划掉/勾过"，不读写了什么。

### 16.4 数据模型

| 表 | 作用 | 关键点 |
|---|---|---|
| `sheetManifests` | 打印时的坐标快照 | 键是 `模板@日期@纸张`；同一天换纸重打会各存一份 |
| `scanBatches` | 一次扫描的识别结果 | `status: pending → applied / discarded`；应用后留档可追溯 |
| `moodLogs` / `diaryEntries` / `toolboxRuns` / `checklists` / `checklistLogs` | 行为层 | 与扫描解耦：扫描只是**一种**写入口 |

### 16.5 失败与降级

- **纸上没有二维码 / 旧纸**（P2 之前打的）：允许手动选模板+日期；此时**没有坐标快照**，
  回填一律标「可能对不上，请逐条核对」，并建议重打。
- **没有摄像头**（桌面浏览器/无权限）：退化为"上传照片"，识别链路相同。
- **自动找角失败**：四角手动点；这是默认就提供的路径，不是应急。
- **识别不确定**：全部进待确认列表，不做自动应用。
- **采样到纸外**：矩形钳制在页内，面积为 0 时按"未勾选"处理。
